## 测试接缝与交付边界

沿用父规格已经确定的部署控制接缝：通过控制操作、实际文件产物、Git 版本、HTTP 响应和状态输出验证行为。局部测试隔离构建输入；完整实验仍运行固定镜像、干净
`npm ci`、完整 `npm run gate` 和真实 Nginx，不用 mock 调用次数证明发布安全。

锁覆盖准备到最终状态记录和候选清理，状态区不挂载到构建器或 Nginx。公开维护信息由显式允许列表投影，不能通过持续改写已发布的不可变版本来更新，也不能暴露私有状态目录。部署失败与实验中“预期失败场景验证通过”分别记录。

提交前必须完成全部本地门禁和真实正负实验、两轮独立审核；第二轮使用新的审核者。推送后再复审精确远端 head，完成 edited、Ready 事件门禁、匹配 SHA 合入、main
CI、验收记录及回读后关闭。没有真实 App/Ruleset、主机管理员操作或 timer 启用授权。

## 控制操作与失败语义

`deploy/deployment_controller.py`
提供共用控制操作。#83 在隔离实验中接入真实构建器、Linux 卷和 HTTP；#84 再包装主机命令、配置与 systemd 安装材料。

| 操作                      | 条件与行为                                                                                                                                                     |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `deploy(sha)`             | 接受完整 40 位 SHA；同一当前成功、失败或暂停 SHA 只记录检查；新 SHA 经过准备、完整构建、产物验证、原子切换、稳定 HTTP 复核后才能记录部署成功                   |
| `deploy(sha, retry=True)` | 只接受失败或暂停 SHA，重新经过完整流程；保留的成功目录不覆盖，仅在新构建的所有公开字节及元数据一致后复用，比较仅排除 `release.json` 的新构建时间 `generatedAt` |
| `rollback(sha)`           | 只接受紧邻上一成功 SHA；复核保留目录、原子回指、HTTP 成功后将撤下版本暂停；不能用再次 rollback 绕过暂停重试                                                    |
| `status()`                | 只读组合严格状态文件、不可变版本指纹与实际服务指针；不一致报错，未完成意图返回 `recovery_required`，不自动修复                                                 |
| `recover()`               | 对已有未完成意图恢复操作前版本并复核 HTTP，清理该意图拥有的候选；完成后才解除恢复门禁                                                                          |
| `cleanup()`               | 只清理已被成功状态明确交出的旧版本；失败保留待清理记录，可重复执行，不撤下当前成功站点                                                                         |
| `publish_status()`        | 在相同锁下生成独立公开投影；损坏的私有记录仅投影固定 `deployment_status_unavailable`，不复制原始内容，不修复原始证据                                           |

准备、构建与健康检查由明确的适配器提供。`PreparationUnavailable`
仅在准备阶段触发至多三次有界尝试；已进入构建的异常不能回到准备重试。输入、依赖、构建与产物失败保留旧站并记录固定阶段码，不输出底层异常字符串。

切换前先持久化操作意图；切换、健康复核或成功状态写入失败时，先尝试原子恢复旧站并再次访问 HTTP。回滚写入或恢复健康检查失败时保留意图，阻止普通部署和显式重试继续。若状态存储持续不可写，操作返回固定写入错误，旧持久化意图仍可供后续显式恢复。首次部署没有旧版本时撤下失败指针，明确记录
`no_previous`，不能把它报告为成功回滚。

锁在状态读取前获取，并持有到状态记录及候选清理结束。第二个真实进程立即得到
`deployment_busy`；锁文件不删除、不替换，退出或被终止后的锁由内核释放。锁与状态目录均为部署用户所有、权限
`0700`，文件为
`0600`，拒绝符号链接、硬链接、非普通文件、重复 JSON 键、不合法字段与超限状态。状态目录不挂载到构建器或 Nginx。

## 状态与公开维护信息

私有状态分别记录最后观察、最后构建成功、最后部署成功、当前、上一成功、失败、暂停 SHA 及相应 UTC 时间。未完成意图与版本指纹用于核验和恢复，不作为公开维护字段。新成功记录持久化后才交出更早版本；只保留当前与紧邻上一成功版本。清理失败时当前站点已成功这一事实仍保留，操作结果单独标记
`cleanup` 失败。

失败候选只有在旧 HTTP 恢复后才被清理，不因后续出现其他 SHA 而遗留未成功版本。若 HTTP 回滚已成功而候选清理失败，分别记录成功的回滚结果和
`cleanup` 错误，保留未完成意图供显式恢复；不能把清理错误伪装成 HTTP 回滚失败。

公开入口为 `/maintenance/deployment.json`，通过受版本控制的 Nginx 精确路径读取
`releases/maintenance/deployment.json`。只发布经过验证的 SHA、时间和固定状态枚举，沿用安全头及
`no-cache, must-revalidate`；不改写版本目录内的任何文件，也不公开私有状态文件、目录、指纹、异常堆栈、配置或正文。宿主适配器应在操作后显式发布投影；投影写入失败属于操作错误，不能用旧投影冒充最新状态。

## 真实实验入口

```sh
npm ci
npm run gate
npm run deployment:lab -- --recovery --output .cache/deployment-lab/recovery-run
```

需要可访问的本地 Linux Docker daemon，缺失运行时即失败。实验使用新建的公开源码 Git
fixture、专属卷与网络；不发布宿主端口，不操作真实 GitHub 内容或主机 timer。输出路径必须尚不存在。结束时只清理本次实验拥有的容器、镜像、卷、网络与工作文件；保留逐阶段
`report.json` 和实验诊断，便于复核失败原因。

正常 v1、健康失败 v2、显式失败重试、暂停后显式重试均执行干净构建和完整门禁。非法输入、依赖与编译故障由实际容器命令拒绝；产物故障注入实际 Astro 文件；切换后移除新版本元数据，使真实 HTTP 返回 404 并触发回滚。两个实际控制进程验证锁竞争，持续运行的同一 Nginx 验证旧站保护、回滚与维护 JSON。只有每个预期失败均被真实观察、恢复行为核对一致，实验才报告通过。该实验已接入
`repository-gate`，不能 skip。
